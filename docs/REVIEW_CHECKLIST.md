# Чек-лист ревью

Инструкция для `reviewer` зашита в `.claude/agents/reviewer.md`. Этот файл — для вас:
как проверять сам контур, а не отдельную задачу.

## Что проверять у ревьювера

Ревьювер — самое уязвимое звено, потому что его вердикт никто не перепроверяет.
Раз в несколько задач проверяйте его вручную:

1. **Подсадите заведомую халтуру.** Возьмите принятую задачу, вручную добавьте в код
   `except Exception: pass` или хардкод под конкретный тест, прогоните ревьювера заново.
   Он обязан дать `FAIL` с точным указанием файла и строки.
2. **Подсадите слабый оракул.** Ослабьте тест так, чтобы он проходил пустой реализацией.
   Ревьювер обязан дать `FAIL` с `ADDRESSEE: test-author`.
3. **Проверьте, что он реально запускает команды.** В транскрипте подагента должны быть
   вызовы Bash с командами из ACCEPTANCE. Если он вынес вердикт, ничего не запустив, —
   вердикт недействителен, а промпт надо ужесточать.

## Признаки, что контур деградирует

| Наблюдение | Что происходит |
| --- | --- |
| Ревьювер месяц не давал ни одного FAIL | либо он штампует, либо задачи стали тривиальными |
| `STATUS: BLOCKED` не приходит никогда | спеки слишком расплывчаты, кодер додумывает молча |
| `STATUS: BLOCKED` приходит на каждой задаче | `allow` слишком узкий или CONTRACT недописан |
| `guard-paths.js` не срабатывал ни разу | проверьте workspace trust — возможно, хуки просто не запускаются |
| FINDINGS содержат «рекомендую рассмотреть» | ревьювер съехал на вкусовщину, вернуть к чек-листу |
| Диффы стабильно превышают бюджет | задачи слишком крупные, дробить |

## Проверка, что хуки вообще живы

```bash
# полный набор кейсов guard (обходы через sed -i, python -c, git -C, docker и т.д.)
node .claude/hooks/guard-paths.test.js

# guard-paths от лица кодера: должен вернуть exit 2 (при записанном task-scope.json)
echo '{"agent_type":"coder","tool_name":"Write","tool_input":{"file_path":"finny-pet/app/src/test/X.kt"}}' \
  | node .claude/hooks/guard-paths.js; echo "exit=$?"

# assert-oracle-intact: должен вернуть exit 2 при изменённом protect-пути
node .claude/hooks/assert-oracle-intact.js; echo "exit=$?"
```

Без `agent_type: "coder"` хук пропускает всё — так задумано: ограничения только для
кодера, главная сессия и остальные роли свободны. Поэтому проверочный вход обязан
нести это поле, иначе `exit=0` ничего не доказывает.

Если первый вернул `exit=0` — контур не защищает ничего. Проверяйте это после
каждого обновления Claude Code, а не только при настройке.

## Разделение вердиктов

`FAIL` бывает трёх адресатов, и путать их дорого:

- **`ADDRESSEE: coder`** — реализация не соответствует спеке. Переоткрыть задачу тому же
  кодеру с FINDINGS в качестве входа.
- **`ADDRESSEE: test-author`** — оракул слаб или неверен. Кодера трогать нельзя, пока
  оракул не переписан: иначе он будет подгоняться под сломанный тест.
- **`ADDRESSEE: orchestrator`** — спека противоречива или неполна. Самый частый случай
  при запуске контура. Чинится переписыванием задачи, а не давлением на агентов.
