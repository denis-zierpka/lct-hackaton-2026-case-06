**Как работать с владельцем**: решения даёт пачкой, пронумерованными ответами на пронумерованный список с
рекомендациями; критерий любой механики — «захочет ли ребёнок играть сам», и «ребёнок не должен залипать много» (№ 47).
Визуальное решает только по картинке — варианты всегда листом/макетом на настоящем фоне (`tools/sheets.py`,
`tools/mock_bakery.py`). **Экраны мест — сцена, а не карточки** (решения 39, 40): житель на полу, небольшое облачко,
короткие числа («6–10»); большой текстовый Panel на экране места — регрессия. Одобрение стиля — только ответ после
показа листа. Когда владелец просит передать работу в новую сессию — заканчивать текущий шаг и передавать, не начинать
новый.

**Урок сессии 9** — WORKFLOW № 37: зонд «пойман» — только если упал ожидаемый тест (`mutation_probe.py`: поле `expect`,

**Уроки сессии 8** — в WORKFLOW правила № 32–36: маршрут с молчаливым промахом касания снимает чужие экраны (лог — греп
«not found» = 0 как критерий; калитка после холодного старта и растущий экран взрослого); `adb install` с путём `/c/…`
из Git Bash молча не ставит APK — A/B мерил одну сборку (путь через `cygpath -w`, флаг сборки после установки);
поиск объекта по разнице снимков не видит мелких правок (порог площади) — рамки брать из прошлой разметки; судья
«ребёнок» вслепую по вырезкам «до/после» вперемешку с самопроверкой на кадрах «до» — различает реальную правку и
находит то, чего не видят остальные линзы (Тоша, монета Кеши); утверждение-счёт о контенте («у N из M») — сверять
по таблице в коде, а не по памяти (два круга ревью). Ещё: правки доков в `docs/` при работающем кодере
запрещены (стоп-хук запишет их на кодера) — готовить в scratch и применять после.
