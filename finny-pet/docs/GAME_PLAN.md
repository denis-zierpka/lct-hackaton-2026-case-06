# План «из приложения в игру»: экраны, трудоёмкость, ассеты

> **Исторический документ:** план перехода от classic к варианту game до версии 1.3.0. Часть решений изменена: дракон заменён щенком, звуки синтезированы `tools/art/sounds.py`, музыка по умолчанию выключена. Актуальное состояние — [REQUIREMENTS_MATRIX.md](REQUIREMENTS_MATRIX.md) и [../CHANGELOG.md](../CHANGELOG.md).

Цель: сохранить экономику, контент и тесты как есть (`domain/`, `content.json`), заменить оболочку так, чтобы ребёнок видел питомца и его комнату, а не формы. Все требования ТЗ (портрет 360 dp, запуск ≤ 5 с, отклик ≤ 1 с, элементы ≥ 48 dp, цвет не единственный сигнал, отключаемые звуки и анимации, без тревоги за питомца) остаются ограничениями.

Оценки в человеко-часах для разработчика, знакомого с Compose. Приоритеты: P0 нужно для демо, P1 сильно улучшает, P2 если останется время.

## Технические заметки

- Библиотеки не нужны: Compose Canvas, `Animatable`, `SoundPool`, VectorDrawable. Lottie (Apache 2.0) добавлять только если дизайнер отдаёт готовые анимации из After Effects.
- Все частицы на одном Canvas, слои питомца в одном `Box`; проверить, что главный экран держит 60 к/с на эмуляторе с 2 ГБ и на устройстве с 3 ГБ.
- Анимации и звук отключаются одним флагом каждая; при выключенных анимациях конечное состояние показывается сразу.
- Иконки потребностей, штампы и ценники дублируют цвет формой и текстом (ТЗ 3.6).
- Грусть питомца: только выражение и реплика «помоги мне», без болезней и таймеров (2.2, 3.5).
