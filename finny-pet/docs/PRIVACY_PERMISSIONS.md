# Разрешения, данные и защита ребёнка

Как «Питомец Финни» выполняет ТЗ 3.4 (разрешения, секреты) и 3.5 (данные, защита ребёнка). Описан сдаваемый вариант game (`ru.finny.pet`, 1.4.0); classic использует тот же манифест и то же хранилище.

## Кратко

| Требование ТЗ | Как выполнено |
|---|---|
| 3.4: только необходимые разрешения, каждое обосновано | В исходном манифесте разрешений нет. В собранном APK одно signature-разрешение от androidx.core — см. ниже |
| 3.4: в репозитории нет паролей, токенов, ключей | `keystore.properties`, `*.jks`, `*.keystore`, `local.properties` в `.gitignore` |
| 3.5: без аккаунта и персональных данных | Аккаунтов нет. Хранится только игровой профиль, из личного — лишь выдуманное имя питомца |
| 3.5: не запрашиваются платёжные данные и сведения о бюджете семьи | Все суммы — игровые монеты, реальные деньги нигде не вводятся |
| 3.5: нет рекламы, подписок, покупок, случайных платных наград, внешних ссылок | Нет ни библиотек для них, ни URL в коде, ни переходов в браузер |
| 3.5: сброс и удаление данных — взрослому, без разработчика | Раздел для взрослого: три действия с подтверждением |

## Разрешения

**Исходный манифест** [`../app/src/main/AndroidManifest.xml`](../app/src/main/AndroidManifest.xml): нет ни одного `<uses-permission>`. Нет интернета, камеры, микрофона, геолокации, контактов, хранилища, уведомлений.

**Собранный APK**: при слиянии манифестов библиотека `androidx.core:core` (1.16.0, приходит транзитивно через Compose) добавляет одно разрешение:

| | |
|---|---|
| Имя | `ru.finny.pet.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` |
| Уровень | `signature`: объявляет и использует само приложение |
| Зачем | Если AndroidX регистрирует приёмник сообщений через `ContextCompat.registerReceiver(..., RECEIVER_NOT_EXPORTED)`, то на Android ниже 13 он закрывается этим разрешением: так чужие приложения не могут слать ему сообщения. На Android 13 и выше вместо разрешения работает системный флаг. Наш код приёмники не регистрирует |
| Почему не опасно | Получить его может только приложение, подписанное тем же ключом. Система выдаёт его при установке сама: пользователю оно не показывается и не запрашивается. Доступа к данным, сети и датчикам оно не даёт. Это ограничение, а не новые права |
| Откуда видно | Отчёт слияния `app/build/outputs/logs/manifest-merger-game-release-report.txt` (строки `permission#…` и `uses-permission#…` из `androidx.core:core:1.16.0`) |

Прочие компоненты, которые приходят из библиотек в итоговый манифест, ни прав, ни сети не добавляют:
- `androidx.startup.InitializationProvider` имеет `exported="false"`;
- `androidx.profileinstaller.ProfileInstallReceiver` защищён системным `android.permission.DUMP`, поэтому писать ему могут только adb и система. Он нужен для профилей ускорения запуска.

**Как проверить** на готовом APK (build-tools 36.0.0, запускать из папки `finny-pet`):

```
# Windows
%LOCALAPPDATA%\Android\Sdk\build-tools\36.0.0\aapt2 dump permissions release\finny-pet-1.4.0-release.apk
# Linux
$ANDROID_HOME/build-tools/36.0.0/aapt2 dump permissions release/finny-pet-1.4.0-release.apk
```

Ожидаемый вывод (1.3.0 проверен на `app/build/outputs/apk/game/release/app-game-release.apk`; у файла сдачи 1.4.0 `aapt2 dump badging` показывает то же одно разрешение):

```
package: ru.finny.pet
permission: ru.finny.pet.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION
uses-permission: name='ru.finny.pet.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION'
```

## Сеть, реклама, аналитика

- **Интернета нет.** Разрешения `android.permission.INTERNET` нет, поэтому система не даст приложению открыть сетевое соединение. Все сценарии работают офлайн.
- **Рекламы, аналитики, платежей нет.** В зависимостях [`../app/build.gradle.kts`](../app/build.gradle.kts) только Compose, Activity, Lifecycle и kotlinx-serialization. Рекламных SDK, аналитики, биллинга и сбора сбоев нет.
- **Внешних ссылок нет.** В Kotlin-коде нет URL, `Intent` в браузер и `LocalUriHandler`.

## Какие данные хранятся

Все игровые данные хранятся в одном файле `filesDir/state.json`, в приватной папке приложения, куда другим приложениям доступа нет. Код: [`../app/src/main/java/ru/finny/pet/data/StateStore.kt`](../app/src/main/java/ru/finny/pet/data/StateStore.kt), модель описана в [`../app/src/main/java/ru/finny/pet/domain/GameState.kt`](../app/src/main/java/ru/finny/pet/domain/GameState.kt) и [DATA_MODEL.md](DATA_MODEL.md).

| Что | Персональные данные? |
|---|---|
| Имя питомца: одно из готовых («Финни», «Пушок», «Бублик») или своё, до 12 символов | Нет, это имя игрового персонажа. Фамилию, возраст, контакты не спрашиваем |
| Вид, цвет, показатели и стадия питомца | Нет |
| Монеты, банки, копилка, план, покупки, мечта (цель), вещи дома, смены, события и их исходы, наклейки, ответы на загадки, увиденные цены, итоги недель, дневник, журнал начислений и конверт; у `classic` — результаты заданий | Нет, всё игровое |
| Настройки: звуки, музыка, анимации, демо-режим | Нет |

Служебные файлы в той же папке:
- `state.json.tmp` появляется на время записи;
- `state.json.bad` остаётся, если файл состояния оказался повреждён при чтении;
- `profileInstalled` и `profileinstaller_profileWrittenFor_lastUpdateTime.dat` пишет библиотека `androidx.profileinstaller` (1.4.0, подключается через `InitializationProvider` в итоговом манифесте). В них отметки об установке профиля ускорения запуска, игровых и личных данных нет.

**Резервное копирование.** `android:allowBackup="false"`, поэтому файл не уходит ни в облачную копию Android, ни в `adb backup`. На Android 12+ этот флаг не запрещает прямой перенос данных между устройствами владельца (D2D при смене телефона): разработчику при этом ничего не передаётся. Запретить и такой перенос можно правилами `dataExtractionRules`, сейчас их нет.

## Сброс и удаление

Действия находятся в разделе для взрослого ([`../app/src/game/java/ru/finny/pet/game/screens/ParentScreen.kt`](../app/src/game/java/ru/finny/pet/game/screens/ParentScreen.kt)). Вход закрыт примером «двузначное × однозначное» (12–19 × 3–9), при ошибке показывается новый пример. Каждое действие требует подтверждения. Логика — [`../app/src/main/java/ru/finny/pet/domain/Economy.kt`](../app/src/main/java/ru/finny/pet/domain/Economy.kt).

| Кнопка | Что происходит |
|---|---|
| «Создать тестовый профиль (демо)» | Новый профиль с включённым демо-режимом, затем питомца создают заново |
| «Сбросить профиль» | Питомец, имя и весь прогресс (покупки, копилка, план, итоги недель) стираются, питомца создают заново. Сохраняются настройки звуков, музыки, анимаций и демо-режим |
| «Удалить профиль и данные» | То же, что сброс, но демо-режим тоже выключается: из прежнего остаются только настройки звуков, музыки и анимаций |

Полностью, вместе с `state.json.bad` и служебными файлами библиотеки, данные удаляются при удалении приложения или через «Настройки Android → Приложения → Питомец Финни → Хранилище → Очистить данные».

## Секреты в репозитории

- Файлы `keystore.properties`, `*.jks`, `*.keystore`, `local.properties` перечислены в [`../.gitignore`](../.gitignore). В git лежит только шаблон [`../keystore.properties.example`](../keystore.properties.example): пароли пустые, путь к ключу и псевдоним — заглушки. Подпись также можно передать переменными `FINNY_STOREFILE`, `FINNY_STOREPASSWORD`, `FINNY_KEYALIAS`, `FINNY_KEYPASSWORD`.
- Проверка: `git ls-files | grep -iE "keystore|\.jks|local.properties"` выдаёт только `keystore.properties.example`.
- Release 1.4.0 для промежуточной сдачи (ТЗ 7.1), как и 1.3.0, подписан debug-ключом (`CN=Android Debug`), потому что `keystore.properties` нет. Постоянный ключ будет к финалу и храниться будет вне репозитория.

## При дальнейшей публикации

Сейчас приложение не обрабатывает персональных данных и не пользуется облаком. Поэтому согласие законного представителя и политика обработки ПДн пока не нужны, а возрастная маркировка — 0+ ([RUSTORE_CARD.md](RUSTORE_CARD.md)). Если появятся аккаунты, облако или аналитика, потребуются:
- обоснование состава и цели данных, срок хранения, удаление, правовое основание;
- согласие законного представителя (ТЗ 3.5);
- соблюдение 152-ФЗ, 436-ФЗ и правил RuStore.

Актуально на версию 1.4.0 (2026-09-29)
