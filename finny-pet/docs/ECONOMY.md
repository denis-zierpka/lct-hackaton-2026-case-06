# Игровая экономика: формулы и правила

Все правила — в одном классе [`Economy.kt`](../app/src/main/java/ru/finny/pet/domain/Economy.kt) (чистый Kotlin, без Android). Состояние профиля — [`GameState.kt`](../app/src/main/java/ru/finny/pet/domain/GameState.kt), числа — `rules` в [`content.json`](../app/src/main/assets/content/content.json) (класс `Rules` в [`Content.kt`](../app/src/main/java/ru/finny/pet/domain/Content.kt), его значения по умолчанию совпадают с файлом). Тесты: [`EconomyTest.kt`](../app/src/test/java/ru/finny/pet/domain/EconomyTest.kt), [`MvpRulesTest.kt`](../app/src/test/java/ru/finny/pet/domain/MvpRulesTest.kt), [`Match3Test.kt`](../app/src/test/java/ru/finny/pet/domain/Match3Test.kt).

Документ описывает сдаваемый вариант `game` (`ru.finny.pet`). Вариант сборки `classic` (`ru.finny.pet.classic`) использует тот же домен и те же правила, в сдачу не входит.

Всё до раздела «Городок» — правила 1.3.0, по которым `game` работает сейчас. Раздел [«Городок»](#городок-движок-среза-1) описывает движок концепции «Городок» (`domain/town`, срез 1): он уже есть и покрыт тестами, интерфейс `game` переходит на него в задаче TOWN-S1d.

## Валюта, доход, журнал

Монеты — игровая валюта, реальной стоимости не имеют. Отрицательного баланса не бывает: каждое списание проверяет `amount ≤ balance`.

| Источник | Сумма | Ограничение | Нужен план |
|---|---|---|---|
| Карманные деньги | +100 | при создании питомца и в начале каждой недели | — |
| Задание | +10 верно / +5 неверно | каждое из 10 заданий — один раз | нет |
| Мини-игра «Монетки в ряд» | 1 за 20 очков | ≤ 30 за неделю | да |
| Бонус взрослого | +10 | ≤ 3 раз за неделю | нет |
| Вопросы питомца | 0 монет, +1 бомба | каждый вопрос верно — один раз | нет |

Каждое изменение баланса пишется в журнал недели `GameState.ledger` (текст + сумма): `Карманные деньги на неделю` +100, `Задание «…»` +10/+5, `Покупка: Корм` −30, `В копилку` −N, `Из копилки` +N, `Игра «Монетки в ряд»` +N (только если N > 0), `Бонус от взрослого: <причина>` +10, `Цель «…» достигнута` 0, `Остаток с прошлой недели` +N. Сумма журнала всегда равна балансу (тест `period end requires plan and scores three rules`).

## Неделя

Неделя — счётчик `period`, а не календарь: она кончается только вызовом `endPeriod`. В `game` его запускает подтверждение «Завершить неделю N?» (кнопка «Спать!»). Открывают это подтверждение кнопка с луной в комнате, которая появляется после подтверждения плана и подписана «Спать» в портретной ориентации и «Завершить неделю» в альбомной, и подсказка «Сейчас» «Завершить неделю», когда всё остальное сделано. Цикл: карманные → план → покупки, копилка, задания, мини-игра → конец недели.

### План

- Три направления: обязательное `M`, желаемое `O`, копилка `S`; все ≥ 0 и `M + O + S ≤ balance`. Отрицательная часть: «Сумма не может быть меньше нуля» (в `game` «−» не опускает часть ниже 0). Сумма больше баланса: «План больше, чем есть монет: X из Y» + «Уменьши одну из частей на N».
- Подтвердить нельзя пустой план (`M + O + S = 0`). При подтверждении: «Вне плана осталось N монет — это запас.» (`N = balance − (M+O+S)`) или «Все монеты распределены.»; при `M = 0` — предупреждение, что еда и уход всё равно понадобятся.
- В `game` ([`PlanScreen.kt`](../app/src/game/java/ru/finny/pet/game/screens/PlanScreen.kt)): кнопки «+»/«−» шагают на `planStep` (10), «+» недоступна при остатке меньше шага; до подтверждения виден остаток «В кошельке: N из B».
- Подтверждённый план не меняется до конца недели. Монеты, пришедшие после (задания, игра, бонус), план не меняют.
- Без подтверждённого плана нельзя: покупать, класть в копилку, играть в мини-игру, завершать неделю. Можно: снимать из копилки, решать задания, отвечать на вопросы питомца, выбирать и забирать цель, получать бонус взрослого.

### Покупки

| Товар | Направление | Цена | Эффект |
|---|---|---|---|
| Корм | обязательное, еда | 30 | сытость +40 |
| Вкусный обед | обязательное, еда | 45 | сытость +50, настроение +5 |
| Шампунь | обязательное, уход | 20 | чистота +40 |
| Расчёска | обязательное, уход | 15 | чистота +25 |
| Ванна с пеной | обязательное, уход | 25 | чистота +20, настроение +5 |
| Мячик | желаемое | 25 | настроение +20 |
| Бантик | желаемое | 15 | настроение +10 |
| Шарик | желаемое | 10 | настроение +8 |
| Книжка сказок | желаемое | 35 | настроение +25 |
| Домик-палатка | желаемое | 60 | настроение +35 |

- Условие: `price ≤ balance`. Иначе «Не хватает N монет: цена P, у тебя B» и варианты: «Выполни задание…» (если есть доступные задания); «Есть дешевле: X за N монет» (самый дорогой товар той же потребности, на который хватает); «Можно взять из копилки, но цель отодвинется» (если `savings ≥ N`); всегда — «Или подожди новую неделю…».
- Эффект: `balance −= price`; `hunger/clean/mood += эффект`, каждый в диапазоне `[0, 100]`.
- После покупки — факт против плана по направлению: «На желаемое потрачено 25 из 20 по плану — больше плана. Не страшно: учти это в следующем плане.» Перерасход разрешён, он влияет только на проверку «Траты по плану».

### Копилка

- Положить: план подтверждён, `0 < amount ≤ balance` → `balance −= amount`, `savings += amount`, `depositedThisPeriod += amount`.
- Снять: `0 < amount ≤ savings`, план не нужен → обратная операция, `withdrawnThisPeriod += amount`. Перед подтверждением — предпросмотр `withdrawPreview`: «В копилке останется X монет вместо Y.»; при цели — «До цели „…“ будет не хватать A вместо B.» и, если срок меняется, «Срок достижения цели: n → m».
- Взнос недели: `factSavings = deposited − withdrawn` (может быть < 0).

### Цель и срок

- Цель — из списка (Самокат 150, Набор красок 80, Конструктор 120, Билет в зоопарк 100) или своя: название из 5 вариантов, цена 50/100/150/200. Смена цели копилку не трогает.
- Осталось: `remaining = price − savings`.
- Средний взнос: `avg = (Σ depositHistory + cur) / (число недель в истории + [cur > 0])`, где `cur = max(factSavings, 0)`. Текущая неделя считается, только когда в ней уже отложено, — поэтому прогноз не проседает в начале недели. `avg = 0`, если недель нет.
- Срок: `eta = ceil(remaining / avg)` недель; `remaining ≤ 0` → 0; `avg = 0` → срок не показывается («Откладывай регулярно — и я посчитаю срок.»).
- Забрать цель: `savings ≥ price` и подтверждение → `savings −= price`, цель уходит в `achievedGoals`, `mood += 30` (до 100); баланс не меняется.

### Награды: задания и бонус взрослого

- Задание: доступно, если ещё не решено и `unlockPeriod ≤ period` (10 заданий, открываются на неделях 1–4) или включён демо-режим (`GameState.demo`, тогда все сразу). Решается один раз: верно → +10 и `mood +5`, неверно → +5 и объяснение.
- Бонус взрослого (`parentBonus`): причина из `parentBonusReasons` (4 варианта) → `balance += 10`, запись в журнал с причиной. Не больше 3 за неделю («На этой неделе все бонусы уже начислены…»), счётчик сбрасывается в новой неделе. План не требует и не меняет. В `game` — блок «Бонус ребёнку» в разделе для взрослого ([`ParentScreen.kt`](../app/src/game/java/ru/finny/pet/game/screens/ParentScreen.kt)): кнопка причины → подтверждение «Начислить 10 монет?».

### Мини-игра «Монетки в ряд»

- Закрыта до подтверждения плана (`miniGameLock`): «Сначала составь план на неделю — игра откроется после него». В `game` кнопка «Игра» в комнате полупрозрачна и вместо поля показывает эту причину; `finishMiniGame` без плана тоже отказывает, монеты и бомбы не меняются.
- Очки ([`Match3.kt`](../app/src/main/java/ru/finny/pet/domain/Match3.kt)): поле 7×6, 15 ходов; обмен без ряда отклоняется и хода не тратит. Ряд из 3 = 10 очков, каждая плитка сверх трёх +10; каскады умножаются на ×1, ×2, ×3… Бомба снимает квадрат 3×3 (10 очков за клетку), хода не тратит, каскады после неё — с ×2.
- Монеты за раунд: `earned = min(⌊score / 20⌋, 30 − miniGameEarned)`. Раундов за неделю сколько угодно, но всего не больше 30 монет; `miniGameEarned` сбрасывается в новой неделе.
- Бомбы: верный ответ на вопрос питомца (`answerQuiz`) → `bombs += 1`, `mood +3`, монет нет; неверный — только объяснение, вопрос можно задать снова. Использованные в раунде бомбы списываются при завершении раунда (`finishMiniGame`: `bombs −= bombsUsed`, не ниже 0); в `game` из раунда выходят только через итог («Закончить» или системное «Назад»). Неиспользованные бомбы переходят в следующую неделю.

## Конец недели

Требуется подтверждённый план. Три проверки, `score` = число выполненных (0–3):

| Проверка | Условие |
|---|---|
| Еда и уход (`mandatoryCovered`) | за неделю куплен хотя бы один товар «еда» и хотя бы один «уход» |
| Траты по плану (`planKept`) | `factM ≤ M` и `factO ≤ O` и `max(factSavings, 0) ≥ S` |
| Копилка выросла (`saved`) | `factSavings > 0` |

Снятие из копилки считается как 0 отложенных, а не как нарушение: при `S = 0` снятие план не проваливает.

Показатели питомца (по порядку):

1. Убывание: сытость −30, чистота −25, настроение −10.
2. Еда и уход куплены не оба: настроение −20; нет еды — сытость ещё −20; нет ухода — чистота ещё −20.
3. `planKept` → настроение +10; `saved` → настроение +10.
4. Каждый показатель ограничивается `[statFloor, 100]` = `[10, 100]`. Пол 10 есть только здесь: в течение недели показатели в `[0, 100]`, но покупки, задания, вопросы и цель их только повышают. Питомец не болеет и не умирает.

Рост: `growth += score`, никогда не уменьшается. Стадия — последний порог `stageThresholds`, не больше `growth`:

| Стадия | Очки роста | Быстрее всего |
|---|---|---|
| Малыш | 0–3 | старт |
| Подросток | 4–8 | после 2 недель |
| Взрослый | 9+ | после 3 недель |

Итог недели (`PeriodSummary` в `history`) хранит план, факт, проверки, рост и отдельно монеты вне плана. Строки итога идут в таком порядке: убывание → еда и уход → план → копилка → рост и стадия → строки «Вне плана» → «Новая неделя: +100 монет карманных денег.»

Строки «Вне плана» (есть только когда сумма > 0):

- `Вне плана: игра «Монетки в ряд» принесла N монет.`
- `Вне плана: бонус от взрослого — N монет.` (N = число бонусов × 10)

Новая неделя: `period += 1`; `balance += 100` (остаток сохраняется); план, покупки, `deposited/withdrawn`, `miniGameEarned`, счётчик бонусов обнуляются; `depositHistory += max(factSavings, 0)`; журнал начинается заново: «Остаток с прошлой недели» (если > 0) + «Карманные деньги на неделю». Копилка, цель, бомбы, рост и решённые задания сохраняются.

## Настроение питомца

`min = min(hunger, clean, mood)`, `avg = (hunger + clean + mood) / 3` (целочисленно):

- `min < faceSadBelow (30)` → грустный: одна забытая потребность важнее игрушек;
- `avg ≥ faceHappyAvg (60)` и `min ≥ needLowBelow (40)` → довольный;
- иначе → спокойный.

Причина (`faceReason`) перечисляет показатели ниже `needLowBelow` (40): «голодный», «хочет помыться», «скучает». В `game` она — описание питомца для TalkBack ([`RoomScreen.kt`](../app/src/game/java/ru/finny/pet/game/screens/RoomScreen.kt)) и первая реплика по нажатию на питомца, если он не доволен; показатели видны полосами. Реплики `chatter.hungry/dirty/bored` тоже выбираются по `needLowBelow`.

### Кошелёк

Кошелёк = `balance` = «Нужное» (`jarNeed`) + «Хочу» (`jarWant`) + запас. Запас вычисляется:
`reserve = balance − jarNeed − jarWant`; до подтверждения плана банки пусты и весь кошелёк —
«Не разложено». Копилка (`savings`) — отдельно от кошелька. Заработок — в конверте следующей
недели (`envelope`), в кошелёк он не входит.

### План недели

- Раскладка до «Готово» — `Economy.setPlan` (как в 1.3.0: `M + O + S ≤ balance`, шаг `planStep`).
- `Town.confirmPlan`: `Economy.confirmPlan`, затем сразу взнос `S` в копилку («сначала заплати
  себе»), `jarNeed = M`, `jarWant = O`; запас — остаток. Пустой план и подтверждение ночью — отказ.
- Взнос в копилку после плана — из запаса или из «Хочу» (`Town.deposit`); снятие из копилки —
  только до плана, в «Не разложено» (`Town.withdraw`); после плана копилка — лишь способ оплаты у
  кассы. Перенос между банками — только восстановление: запас → «Нужное», «Хочу» → «Нужное».
- Предпросмотры (`depositPreview`, `withdrawPreview`, `transferPreview`) показывают движение монет
  и срок мечты в конвертах «≈ N ✉» (`Economy.goalEta`); снятие до плана при `S > 0` и перенос
  сверх `M − factM` предупреждают, что штампа «По плану» не будет.

### Касса (`Town.quote`, `Town.buyAt`)

Цена — из лавки (`shops[].sells`), поверх — `PRICE`/`OFFER` событий, пришедших на этой неделе (с `until = DAY_END` — только в день прихода)
(`OFFER` показывает и прежнюю цену). Родная банка: нужное — «Нужное», хочу — «Хочу»,
непредвиденное — запас.

| Категория | Источник | Когда можно | Откуда монеты |
|---|---|---|---|
| нужное | «Нужное» | хватает в «Нужном» | «Нужное» |
| нужное | запас | «Нужного» не хватает, запас > 0, запас + «Хочу» покрывают остаток | всё «Нужное», остаток из запаса, если мало — из «Хочу» |
| нужное | из «Хочу» | «Хочу» покрывает нехватку | всё «Нужное» + нехватка из «Хочу» |
| хочу | «Хочу» | хватает в «Хочу» | «Хочу» |
| хочу | из «Нужного» | «Нужное» покрывает нехватку | всё «Хочу» + нехватка из «Нужного» |
| непредвиденное | запас | запас > 0 и запас + «Хочу» покрывают цену | запас, остаток из «Хочу» |
| непредвиденное | «Хочу» | хватает в «Хочу» | «Хочу» |
| любое | копилка | копилки хватает | копилка (банки не трогаются) |

Запас на «хочу» не идёт («Запас — на нужное и на всякий случай. Хотелки — из банки «Хочу»»).
При нехватке касса называет обе суммы («В «Хочу» 10, мячик стоит 25. Не хватает 15» и «Запас 12 —
на нужное и на всякий случай») или весь кошелёк («Не хватает 28: в кошельке 32, домик-палатка 60»)
и предлагает только выполнимые варианты, не больше трёх на экране:
нужное — [Дешевле] [Добавить из запаса] [Взять из «Хочу»], под «Ещё» — копилка;
хочу — [Дешевле] [Подождать нового конверта] [Сделать мечтой] (при нехватке кошелька — в обратном
порядке), под «Ещё» — перенос из «Нужного» и копилка; непредвиденное — запас, «Хочу», составная
оплата, копилка (отложить нельзя). В предпросмотре — строка «Штамп «По плану» на этой неделе не
получится», если именно эта оплата ломает правило плана недели (то же правило, что в конце недели).
Купленная вещь с `keep` уходит с полки в сундук (`owned`) и встаёт на первое свободное место своего
типа (`town.spots`: пол, стена, стол; цветок и кресло стоят на своих местах). В демо робот, змей и
вертушка (события с `demo.keepOnShelf`) с полки не уходят. Покупка в лавке пишет строку дневника
«Купили у реки: каша».

### Дни и конец недели

- Неделя — `town.rules.daysPerWeek` = 3 дня, счётчик `day`, а не календарь.
- `Town.sleep`: без подтверждённого плана — отказ (раскладка); иначе ночь (`asleep`), день не
  меняется; строка дня — из дневника. `Town.wake`: утро; после обычной ночи `day + 1`, после итога
  недели (план новой недели ещё не подтверждён) день остаётся 1. Сон в последний день — конец
  недели (`Town.endWeek`); в демо конец недели доступен с любого дня.
- `Town.endWeek`: `Economy.endPeriod` (три проверки, убывание, рост, карманные — как выше), затем
  конверт приходит: `balance += envelope`, строки конверта — в журнал отдельными строками; банки
  обнуляются, день 1, ночь, смены недели — 0. Итог недели получает `shiftEarned` и `parentBonus` из
  строк конверта. Утро после итога: «Новый конверт: карманные 100 + зарплата N + бонус N» (нулевые слагаемые не пишутся).
- Заготовка следующего плана — прошлый план (неподтверждённый); если он больше нового кошелька,
  избыток снимается с «Хочу», потом с «В копилку», потом с «Нужного».
- «Что поменяем?» (`Town.planTweaks`, до трёх поправок шагом `planStep`): «Нужное +10» — если еда и
  уход куплены не оба или нужного потрачено больше плана; поправки из исходов MISTAKE событий недели;
  «В копилку +10» — если есть мечта. «Нужное +10» и «В копилку +10» при нехватке кошелька берут
  недостающее из «Хочу»; «Запас +10» = «Хочу −10».

### Смены, «Загадка Бори», бонус взрослого (TOWN-S1b)

Тесты: `ShiftTest`. Работы — `town.jobs`: пекарня «Булочки в ряд» (`MATCH3`), «Помочь Марте»
(`TAPS`, три кнопки-поручения), касса (`CHANGE`, срез 2), курьер (`TAPS`, открывает мечта «Самокат»).

- Лимит: `town.rules.shiftsPerWeek` = 3 оплачиваемые смены в неделю на все работы вместе; счётчик
  `shiftsThisPeriod` обнуляется в конце недели. Оплачиваемые смены открыты и до плана (решение 4).
- Оплата смены = база по уровню работы + надбавка: `MATCH3` — `min(shiftBonusMax, ⌊счёт / 30⌋)`,
  `TAPS` — 0 (работа без ловкости, база гарантирована), `CHANGE` — `min(shiftBonusMax, верных сдач)`;
  `shiftBonusMax` = 4. Бомбы поднимают счёт, но не потолок надбавки.
- Уровни мастерства: пороги `jobLevelShifts` = 0 / 6 / 15 оплачиваемых смен на этой работе, база
  `jobs[].baseByLevel` (пекарня и Марта 6 / 7 / 8, курьер 8 / 9 / 10), бомбы уровня
  `jobLevelBombs` = 0 / 1 / 2 (только пекарня). Смена оплачивается по уровню до неё.
- Вся оплата — в конверт следующей недели строкой «Смена: {работа}» (`envelope`); кошелёк, банки и
  проверка плана недели от смен не меняются. Итог: «База 6 + 3 за булочки. ✉ +9 — придёт с новым
  конвертом», «Почему?» — прогресс («Боря: 4 из 6 смен до уровня 2» или «новый уровень 2! База теперь
  7»), «Карманные приходят каждую неделю, зарплата — когда поработаешь».
- После трёх смен — игра ради рекорда без монет (`records`), только после плана и только у игр со
  счётом (`MATCH3`, `CHANGE`). Ночью работа закрыта.
- «Загадка Бори» (`town.quiz`, 15 вопросов): одна загадка за заказ пекарни (`riddleAsked`, сбрасывает
  конец смены пекарни); верный ответ — бомбочка (`quizBombReward`) в `bombs`, неверный — объяснение,
  вопрос уходит в конец очереди. Монет и показателей питомца загадка не даёт. Ответы — в своём списке
  `riddles`: ответы викторины 1.3.0 (`quizResults`) загадки не снимают. После 15 верных загадки нет.
- Бонус взрослого (`Town.parentBonus`): 10 монет (`parentBonusAmount`), до 3 в неделю, причина из
  `town.parentBonusReasons` — в конверт следующей недели строкой «Бонус от взрослого: {причина}»;
  взрослый видит «Придёт в новом конверте ребёнка». Сейчас раздел взрослого `game` ещё начисляет
  бонус по правилу 1.3.0 (сразу в кошелёк) — перевод на `Town.parentBonus` в задаче TOWN-S1d.

### Мечта из вещи, холодильник, миграция

- «Сделать мечтой» — у вещи с `keep` от `customGoalFromItemMin` (50) по базовой цене лавки: цель
  `item:<id>`; получив её, ребёнок получает и вещь в дом. Что открывают мечты `town.goals` — срез 2.
- Холодильник (`seenPrices`) при входе в лавку запоминает самую низкую цену недели и лавку.
- Сохранение 1.3.0 (`stateVersion = 0`) переносится один раз: банки из плана (`M − factM`,
  `O − factO`, не больше кошелька), keep-покупки недели — в дом, день 1; монеты не появляются и не
  исчезают. Невнесённая в 1.3.0 копилка плана остаётся в запасе.

## Склонение «монет»

`Economy.coins(n, case)` согласует слово с `|n| mod 100`; в сообщениях `Economy` слово после числа идёт через неё (кроме фиксированного «0 монет»). Срок — `Economy.weeks(n)` (неделя/недели/недель).

| Падеж | 1, 21, 101 | 2–4, 22–24 | 0, 5–20, 25–30 |
|---|---|---|---|
| `NOM` («осталось N») | монета | монеты | монет |
| `ACC` («получает N», «за N») | монету | монеты | монет |
| `GEN` («не хватает N») | монеты | монет | монет |

## Пример: демо-профиль, 2 недели

Пересчитан по коду (`rules` из `content.json`); показатели — сытость/чистота/настроение.

```
НЕДЕЛЯ 1. Баланс 100, копилка 0, питомец 70/70/70, рост 0
План 50/20/30 → «Все монеты распределены.»
Задание «С чего начать?» верно        +10 → 110, настроение 75
Задание «Соблазн» неверно              +5 → 115
Корм −30 → 85 (сытость 70+40 → 100)
Шампунь −20 → 65 (чистота 70+40 → 100)
Бантик −15 → 50 (настроение 75+10 = 85)
Домик-палатка 60 → «Не хватает 10 монет: цена 60, у тебя 50»,
  «Есть дешевле: Книжка сказок за 35 монет»
Цель «Самокат» 150; в копилку 20 → баланс 30, копилка 20;
  avg = 20/1 = 20, срок ⌈130/20⌉ = 7 недель
Вопрос питомца верно → настроение 88, бомб 1
Мини-игра: 250 очков, 1 бомба → +⌊250/20⌋ = +12 → 42, бомб 0; до лимита ещё 18
Журнал: 100+10+5−30−20−15−20+12 = 42 = баланс
Конец недели: еда и уход ✓; план ✗ (в копилку 20 < 30); копилка ✓ → score 2
  Питомец: 100−30 = 70 / 100−25 = 75 / 88−10+10 = 88 → довольный
  Рост 0+2 = 2 (Малыш, до Подростка 2)
  «Вне плана: игра „Монетки в ряд“ принесла 12 монет.»
  Баланс 42+100 = 142; depositHistory [20]; срок: avg 20 → ⌈130/20⌉ = 7 недель

НЕДЕЛЯ 2. Баланс 142, копилка 20, питомец 70/75/88, рост 2
План 60/30/40 → «Вне плана осталось 12 монет — это запас.»
Вкусный обед −45 → 97 (сытость 100, настроение 93)
Расчёска −15 → 82 (чистота 75+25 = 100)
Мячик −25 → 57 (настроение 93+20 → 100)
В копилку 50 → баланс 7, копилка 70; avg = (20+50)/2 = 35, срок ⌈80/35⌉ = 3 недели
Предпросмотр «Забрать 20» (отменён): останется 50 вместо 70;
  не хватать 100 вместо 80; срок 3 недели → 4 недели (avg (20+30)/2 = 25)
Задание «Сколько недель?» верно       +10 → 17, настроение 100
Бонус от взрослого «Помощь по дому»  +10 → 27 (план не меняется)
Журнал: 142−45−15−25−50+10+10 = 27 = баланс
Конец недели: еда и уход ✓; план ✓ (60≤60, 25≤30, 50≥40); копилка ✓ → score 3
  Питомец: 70 / 75 / 100−10+10+10 = 110 → 100 → довольный
  Рост 2+3 = 5 → «Финни вырос! Теперь подросток.»
  «Вне плана: бонус от взрослого — 10 монет.»
  Баланс 27+100 = 127; журнал [+27 остаток, +100 карманные]
  depositHistory [20, 50]; срок ⌈80/35⌉ = 3 недели
```

Актуально на версию 1.3.0 (2026-09-25)
